> **${var}** — Optional version tag override (e.g. `"2.1.0"`). If empty, derives version from `skills.json` total count and today's date.

Today is ${today}. Read `memory/MEMORY.md` for project context and active MCP registry goals.

## Overview

Reads `skills.json` for the full skill catalog and `mcp-server/src/index.ts` for the tool names exposed by the vigil-mcp server. Generates or updates three files in `docs/`:
- `docs/smithery.yaml` — Smithery configuration file
- `docs/smithery-manifest.json` — MCP Registry submission manifest
- `docs/smithery-submission.md` — human-readable submission guide

Opens a PR via `gh` CLI if any file changed.

---

## Steps

### 1. Read source data

**Read `skills.json`:**
Extract:
- `version` field
- `total` — total skill count
- `categories` map
- `skills` array — extract `slug`, `name`, `description`, `category`, `schedule`, `var` for each skill

**Read `mcp-server/src/index.ts`:**
Extract all tool definitions — look for `server.setRequestHandler` or `tool(` invocations. For each tool, extract:
- Tool name (e.g. `run_skill`, `list_skills`, `get_skill`)
- Description string

If `mcp-server/src/index.ts` does not exist, check `mcp-server/src/` for other `.ts` files and search for tool definitions there.

**Derive version:**
- If `${var}` is set, use it as the version string.
- Else: version = `${skills_total}-skills-${today}` (e.g. `123-skills-2026-05-22`)

### 2. Generate `docs/smithery.yaml`

Write `docs/smithery.yaml`:

```yaml
# Smithery configuration — https://smithery.ai/docs/config#smitheryyaml
# Auto-generated by skills/smithery-manifest on ${today}. Do not edit by hand.

startCommand:
  type: stdio

configSchema:
  type: object
  properties:
    repoPath:
      type: string
      description: >
        Absolute path to a local clone of the vigil repo.
        The MCP server reads skills.json from this path and dispatches
        `claude -p` from it. Defaults to walking up from the installed
        package; set this when the server cannot locate its own repo root.
      default: ""
  required: []

commandFunction:
  |-
    config => ({
      command: 'node',
      args: [(config.repoPath || '.') + '/mcp-server/dist/index.js'],
      env: process.env
    })

exampleConfig:
  repoPath: "/Users/you/code/vigil"
```

### 3. Generate `docs/smithery-manifest.json`

Write `docs/smithery-manifest.json`:

```json
{
  "schema_version": "2025-03-26",
  "generated_at": "${today}",
  "name": "vigil",
  "display_name": "Vigil — Autonomous Agent Skills",
  "description": "An autonomous agent framework with ${total} skills across ${category_count} categories. Runs on GitHub Actions via Claude Code. Skills cover research, crypto, social, dev, and productivity workflows.",
  "version": "${version}",
  "homepage": "https://github.com/$GITHUB_REPOSITORY",
  "repository": "https://github.com/$GITHUB_REPOSITORY",
  "license": "MIT",
  "categories": ["productivity", "research", "automation"],
  "tools": [
    $(for each tool extracted from mcp-server/src/):
    {
      "name": "${tool_name}",
      "description": "${tool_description}"
    }
  ],
  "skills_catalog": {
    "total": ${total},
    "categories": {
      $(for each category: "${category_key}": ${count})
    },
    "by_category": {
      $(for each category: "${category_key}": [
        $(for each skill in category: {"slug": "${slug}", "name": "${name}", "description": "${description}"})
      ])
    }
  },
  "config_schema": {
    "type": "object",
    "properties": {
      "repoPath": {
        "type": "string",
        "description": "Absolute path to a local clone of the vigil repo.",
        "default": ""
      }
    },
    "required": []
  }
}
```

Ensure the JSON is valid — parse-check by re-reading after writing.

### 4. Generate `docs/smithery-submission.md`

Write `docs/smithery-submission.md`:

```markdown
# Vigil — Smithery MCP Registry Submission

*Auto-generated by skills/smithery-manifest on ${today}*

## Overview

Vigil is an autonomous agent framework with **${total} skills** across ${category_count} categories. Powered by Claude Code, running on GitHub Actions. Skills cover research, crypto/DeFi monitoring, social media management, developer tooling, and productivity automation.

## MCP Server

The `vigil-mcp` server exposes ${tool_count} tools:

$(for each tool: "### `${tool_name}`\n${tool_description}")

## Skills Catalog

Total: **${total} skills**

$(for each category: "### ${category_name} (${count} skills)\n$(for each skill in category: "- **${name}** — ${description}")\n")

## Installation

\`\`\`bash
# Install via Smithery
npx @smithery/cli install vigil

# Or manually: clone and configure
git clone https://github.com/$GITHUB_REPOSITORY
cd vigil
npm install --prefix mcp-server
npm run build --prefix mcp-server
\`\`\`

## Configuration

Set `repoPath` in your Claude Desktop config to the absolute path of your vigil clone.

\`\`\`json
{
  "mcpServers": {
    "vigil": {
      "command": "node",
      "args": ["/path/to/vigil/mcp-server/dist/index.js"],
      "env": {}
    }
  }
}
\`\`\`

## Links

- GitHub: https://github.com/$GITHUB_REPOSITORY
- Smithery listing: https://smithery.ai/server/vigil
- MCP Registry: https://github.com/modelcontextprotocol/servers
```

### 5. Check for changes

```bash
git diff --name-only docs/smithery.yaml docs/smithery-manifest.json docs/smithery-submission.md
```

If no files changed (identical to HEAD), log and stop:
```
### smithery-manifest
- No changes detected — docs are current
```
Stop — no PR, no notification.

### 6. Open a PR with the changes

```bash
git checkout -b smithery-manifest/${today}
git add docs/smithery.yaml docs/smithery-manifest.json docs/smithery-submission.md
git commit -m "docs(smithery): regenerate manifest — ${total} skills, ${version}"
gh pr create \
  --title "docs(smithery): regenerate manifest — ${total} skills" \
  --body "Auto-generated by smithery-manifest skill on ${today}.

Changes:
- skills.json total: ${total}
- Version: ${version}
- Tools documented: ${tool_count}

Merge to keep the Smithery listing current." \
  --base main \
  --head smithery-manifest/${today}
```

Extract the PR URL from `gh pr create` output.

### 7. Log and notify

Append to `memory/logs/${today}.md`:
```
### smithery-manifest
- Skills total: ${total}
- Version: ${version}
- Tools: ${tool_count}
- Files updated: docs/smithery.yaml, docs/smithery-manifest.json, docs/smithery-submission.md
- PR: ${pr_url}
```

```
./notify "*Smithery Manifest — ${today}*

Regenerated submission docs for ${total} skills.

Version: ${version}
Tools: ${tool_count}
PR: ${pr_url}"
```

## Required secrets

None beyond standard `gh` CLI auth (uses `GITHUB_TOKEN` from GitHub Actions environment).

---

## Sandbox note

All operations are local file reads and writes plus `gh` CLI commands. No external API calls needed. `git` and `gh` work natively in the GitHub Actions sandbox. The only external touch is `gh pr create`, which uses the built-in `GITHUB_TOKEN`.

## Constraints

- Never edit `docs/smithery.yaml` or `docs/smithery-manifest.json` by hand when this skill is active — it will overwrite manual edits on next run.
- Always open a PR — never push directly to `main`.
- If `skills.json` does not exist or is malformed, abort with a clear log message.
- Validate JSON output before committing — malformed JSON breaks registry submissions.
